## 💡 为什么需要 Universal Novel Engine？

目前绝大多数 AI 辅助写作方案往往在写到 20-30 万字时遭遇**“断崖式崩盘”**：
1. **大纲塌方与流水账**：单章频繁切换 4~5 个场景，越写越散，严重缺乏主心骨；
2. **大段心理独白灌水**：AI 动辄输出几百字内心活动或大道理，彻底失去故事代入感；
3. **配角过载与引路人拐杖**：前 10 章轰炸式出场十几个角色，引路导师长期待在主角身边沦为智能拐杖；
4. **伏笔突兀如机械降神**：需要揭秘时，突然由反派或主角硬打补丁；
5. **严重词穷与套话复读**：满篇皆是*“深吸一口气”*、*“嘴角勾起一抹冷笑”*、*“倒吸一口凉气”*、*“夕阳如血”*。

**Universal Novel Engine v2.1** 基于白金小说全量逆向工程，提出**“四维叙事结构配比”、“四波次人物登场脉冲”、“杜盟代谢律”与“超微颗粒度细纲规范”**，由外骨骼状态机严格控制逻辑与记忆，让大模型稳定输出白金级质感网文。

## 📊 白金神作的“绝对量化公约数” (3,038章全量统计)

基于对《覆汉》《黜龙》《牧神记》全量 3,038 章节（1,770 万字）的 Python 自动化逆向工程，本引擎固化了如下黄金法则：

| 维度 / 指标 | 低质网文 / AI 默认输出 | 白金神作均值标准 | 引擎硬性约束机制 |
| :--- | :--- | :--- | :--- |
| **动作与物理受阻** | < 25%（虚空放波/站桩） | **45.0% ~ 52.0%** | 必须描写受力阻滞、兵刃形变与机体生理衰竭 |
| **动作交织对白** | < 20%（无头裸台词） | **40.0% ~ 46.0%** | 台词前后 100% 绑定肢体微动作或器物交互 |
| **环境与度支风物** | > 30%（长篇水风景） | **7.0% ~ 10.0%** | 仅用于章首定场或转场，严格交代物价粮饷风物 |
| **纯内心独白** | > 15%（大段心理戏） | **< 1.2%（严禁灌水）** | 超过 2.5% 质检直接报错；所有算计借微动作外化 |
| **单章微场景密度** | 4 ~ 6 个（走马观花） | **1.2 ~ 1.8 个** | 单章专注打透 1 个核心事件与情绪兑现 |
| **第一波人物数量** | > 8 位（乱报菜名） | **≤ 4 位主要角色** | 主角 + 引路人 + 忠勇伴行 + 远景虚写 |
| **引路人寿命** | 终身跟随（变成拐杖） | **第 15~35 章必退场** | **杜盟代谢律**：使命达成即体面牺牲或调离 |

> 完整实证白皮书参见：[`docs/白金小说大纲逆向与细纲工程标准白皮书.md`](docs/白金小说大纲逆向与细纲工程标准白皮书.md)

## 📦 开箱即用预设包 (Genre Presets)

系统内置 4 套完整合规题材预设，自动加载专属细纲模版、人物声纹、四波次规划与冷却规则：

- 🏛️ **`history`（历史权谋）**：汉唐明清官制礼制、户部度支算学、士族豪强博弈、引路老吏传承（参考《覆汉》《黜龙》）。
- ⚔️ **`xuanhuan`（高武变法）**：几何算学道法革新、神为民用、大荒老实人反差、人皇断柄祖神器（参考《牧神记》）。
- 🏔️ **`xianxia`（古典仙侠）**：古典修真、丛林资源竞争、低调谨慎求道、法宝灵药实物锚定（参考《凡人修仙传》《赤心巡天》）。
- 🎩 **`western_fantasy`（诡秘西幻）**：维多利亚蒸汽克苏鲁、火枪转轮装填、理性疯狂阈值、金镑物价经济学（参考《诡秘之主》）。

## 🚀 5 分钟快速上手

### 1. 克隆仓库
```bash
git clone https://github.com/ningjiucheng3-web/platinum-novel-engine.git
cd platinum-novel-engine
chmod +x bin/novel
```

### 2. 初始化你的第一部小说
选择题材预设（如历史权谋 `history`）：
```bash
./bin/novel init --genre history --dir ./my_novel
```
这会在 `my_novel/state/` 下自动生成：
- `character_registry.json`（四波次人物规划与声纹习惯）
- `volume_outline.json`（包含第 1 章超微细纲分镜）
- `clues_ledger.json`（伏笔生命周期账本）
- `imagery_cooldown.json`（反套话冷却表）

### 3. 生成并定制超微颗粒度细纲模板
```bash
# 生成第 2 章超微细纲模板并直接写入大纲
./bin/novel beat-template 2 --apply --dir ./my_novel
```

### 4. 一键全面合规审查 (Validate)
在动笔前验证大纲细纲合规性、四波次人物节奏与伏笔生命周期：
```bash
./bin/novel validate all --dir ./my_novel
```
输出示例：
```text
==================================================
  Universal Novel Engine 工程合规性审查
==================================================
[1/3] 检查章节细纲规范 (共 1 章)...
  ✅ 第 1 章细纲合规: 落雪按刀，度支疑云
[2/3] 检查四波次人物脉冲与杜盟律...
  ✅ 四波次人物脉冲节奏合规！引路人代谢机制已就绪。
[3/3] 检查契诃夫之枪 (伏笔生命周期)...
  ✅ 伏笔生命周期监控正常，无遗忘之枪！
==================================================
  🏆 审查结果: 全部模块符合白金级工程规范 (PASSED)
==================================================
```

### 5. 一键编译当前章生产级 Prompt
```bash
./bin/novel prompt 1 --dir ./my_novel
```
编译器将自动抓取上一章末尾物理尾流、展开当前章场景分镜、配置在场角色声纹禁忌、提取激活伏笔，并注入 48/42/9/1 叙事配比与段落预算。

### 6. 运行四维叙事质检机与状态机推进
将模型生成的章节正文送入质检机：
```bash
./bin/novel qa 1 --file ./my_novel/ch01.txt --dir ./my_novel
```
审查报告：
```text
==================================================
  第 1 章 四维叙事质检报告
==================================================
通过状态: ✅ 通过 (PASSED)
总 字 数: 3520 字 | 总自然段: 62 段 | 段均长: 56.7 字
短段落率: 51.6% (目标>40%) | 对话字数比: 28.3%
对白穿插率: 84.2% (目标>65%) | 估算独立场景: 1 个 (白金标准1.2-1.8)

【四维叙事结构配比】:
  - 动作与物理受阻: 48.5% (白金均值 ~48%)
  - 动作交织对白:   41.8% (白金均值 ~42%)
  - 环境与度支风物: 8.8%  (白金均值 ~9%)
  - 纯内心独白:     0.9%  (白金严控 <1.5%)

【捕捉具象物理词】: 算筹, 骨, 滞涩, 脱手, 崩裂
==================================================
```
通过后将**自动归档章节文本、更新伏笔状态为 `watered`、将套话推入冷却期、标记大纲章节为 `completed`**！

### 7. 查看进度与四波次状态总览
```bash
./bin/novel status --dir ./my_novel
```

## 🤖 Antigravity / Agent 装载方式

本项目原生兼容 **Google Antigravity** 与 **Claude Code** 标准技能系统：

1. **全局安装**：
   ```bash
   ln -s $(pwd) ~/.gemini/antigravity/skills/universal-novel-engine
   ```
2. **在对话中直接唤起**：
   > *"加载 `universal-novel-engine` 技能，根据当前状态机为我编译第 2 章生产 Prompt 并写出正文。"*
